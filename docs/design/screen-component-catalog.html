RoomForge Design System Draft

화면별 컴포넌트 카탈로그

RoomForge를 더 정교하고 예쁜 제품으로 다듬기 위한 화면 단위 UI 컴포넌트 설명서입니다. 실제 구현 전, 각 화면에서 필요한 컨트롤, 상태, 피드백, 캔버스 요소, 접근성 규칙을 한 곳에서 확인하도록 설계했습니다.

전역 컴포넌트

global
  • App shell상단 제품명, 프로젝트 선택, 저장 상태, 계정 메뉴를 포함한 조용한 작업형 네비게이션.
  • Command bar주요 실행 버튼은 아이콘과 짧은 라벨 조합. 저장, 내보내기, 재시도, 보기 전환을 일관된 위치에 배치.
  • Status chip`processing`, `Needs review`, `failed`, `saved` 같은 상태를 색상과 텍스트로 동시에 표현.
  • Inline notice권한, 네트워크, 품질 경고는 화면 흐름을 막지 않는 영역형 메시지로 표시.
  • Dialog프로젝트 생성, 삭제 확인, 재시도 확인처럼 사용자의 명시적 결정을 요구할 때만 사용.

Design Rules For Implementation

이 카탈로그를 실제 Flutter/Three.js 화면으로 옮길 때 지켜야 할 실무 규칙입니다.

Screen density

RoomForge는 작업형 도구입니다. 넓은 hero나 마케팅형 설명보다 프로젝트, 상태, 캔버스, inspector를 빠르게 스캔하는 밀도가 우선입니다.

Canvas hierarchy

2D/3D 작업면은 화면의 주인공입니다. 캔버스를 장식 카드 안에 가두지 말고, 도구/상태/inspector가 캔버스를 보조하게 배치합니다.

State clarity

색상만으로 상태를 전달하지 않습니다. 후보/확정/선택/오류는 텍스트, outline, 아이콘, 요약 문장을 함께 사용합니다.

Manual fallback

CV 결과는 틀릴 수 있습니다. 후보 추가, 라벨 변경, 삭제, 수동 보정은 항상 가까운 위치에서 접근 가능해야 합니다.

Data boundary

사용자 화면은 Firebase/Firestore 용어를 노출하지 않습니다. admin 화면만 id, artifact, provider, rule 상태를 운영자 문맥으로 보여줍니다.

Do

  • 아이콘 버튼에는 hover tooltip 또는 인접 라벨을 제공합니다.
  • 숫자 입력은 stepper, slider, 직접 입력을 상황에 맞게 조합합니다.
  • 저장/업로드/재구성 상태는 화면을 떠나도 이해 가능한 텍스트로 남깁니다.
  • 캔버스 선택 상태는 outline, 핸들, inspector 제목까지 동기화합니다.

Do Not

  • 사용법 설명을 화면 안에 길게 쌓아 작업 흐름을 가리지 않습니다.
  • 모든 섹션을 떠 있는 카드처럼 만들지 않습니다.
  • 보라/파랑 계열만 반복하는 단조로운 팔레트를 만들지 않습니다.
  • 오류 메시지에 내부 Firebase 규칙이나 protected data를 그대로 노출하지 않습니다.
